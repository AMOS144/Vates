# Vates Hacker News 发布设计

## 目标

以 `Show HN` 形式直接提交 GitHub 仓库，优先获得推理系统、MLX 与 Apple Silicon 开发者的技术讨论和潜在贡献。

## 发布策略

Hacker News 不沿用知乎和小红书的营销表达。标题只说明项目做了什么，不使用“碾压”“满血”等夸张措辞，也不把约 8.23–8.27 GiB，MLX `get_peak_memory` 的张量分配在途高水位描述成“8 GB Mac 可以运行”。该指标不是进程 RSS 或系统总占用。

推荐标题：

> Show HN: Vates – SSD-backed expert streaming for Qwen3-Next on Apple Silicon

提交地址：

> https://github.com/AMOS144/Vates

## README 国际化

1. 将当前中文 `README.md` 完整保留为 `README.zh-CN.md`；
2. 将 `README.md` 改为结构一致、可独立阅读的英文版本；
3. 两个文件顶部提供 `English | 简体中文` 切换入口；
4. 英文版保留安装、数据准备、配置、基准结果、正确性、测试、FAQ、贡献和许可证等全部核心内容；
5. 不逐字硬译中文，而是使用自然、克制的英文技术写作；
6. 两个版本都明确记录基准环境：
   - MacBook Pro；
   - Apple M5，10 核；
   - 32 GB 统一内存；
   - 1 TB 内置 Apple SSD；
7. 两个版本都明确说明约 8.23–8.27 GiB 是 MLX `get_peak_memory` 的张量分配在途高水位，不是进程 RSS 或系统总占用；设备仍需为系统与非 MLX 分配保留额外统一内存。

## HN 发布包

新建 `docs/marketing/hacker-news-vates-launch.md`，内容包括：

1. 最终推荐标题及两个备用标题；
2. GitHub 提交链接；
3. 供作者亲自写首评时使用的事实提纲；
4. 发布前检查清单；
5. 对常见问题的事实核对卡。

HN 官方规则禁止发布生成文本或 AI 润色文本，因此发布包不提供可直接复制的评论。首评必须由作者本人用自己的语言从零撰写，事实提纲依次覆盖：

- 项目解决的问题：41 GB 的 4-bit MoE 权重无法在低内存路径中全量常驻；
- 核心方法：专家权重保留在 SSD，按真实路由读取，并复用未来层 gate 做跨层预取；
- 实测环境与结果：M5 MacBook Pro、32 GB 统一内存、内置 SSD，约 8.23–8.27 GiB，MLX `get_peak_memory` 的张量分配在途高水位，以及约 13–15 tok/s；明确该高水位不是进程 RSS 或系统总占用；
- 正确性边界：预测失败时回退到 demand 路径，真实 gate 路由不变，并使用容量不变性与逐字节校验；
- 项目限制：当前只面向 Apple Silicon、MLX 和兼容的 Qwen3-Next-80B-A3B 4-bit 模型；
- 讨论邀请：重点征求对缓存策略、预取调度、SSD 争用和其他 MoE 模型适配的反馈。

## 评论区答复范围

为以下问题准备事实核对卡，不生成可直接粘贴的答复：

1. “约 8.23–8.27 GiB 的 MLX 分配高水位”是否意味着能在 8 GB Mac 上运行；
2. 与 mmap、虚拟内存或系统 swap 有什么区别；
3. 为什么 SSD 读取还能达到交互式速度；
4. 13–15 tok/s 的测试硬件和测量方式；
5. 是否会降低模型质量或改变路由；
6. 为什么只支持 Apple Silicon 和 MLX；
7. 是否支持其他 MoE 模型；
8. 模型权重为什么没有包含在仓库中。

答复只引用仓库中已经验证的事实。对尚未测试的设备、模型和性能不作推断性承诺。

发布包同时披露：当前实验报告并非一套统一的最终 benchmark，部分报告为中文，尚无第三方复现；官方规则要求作品可尝试，但不要求发布前已有第三方复现，不能虚构外部验证，也不能把缺少第三方复现本身写成绝对禁止 Show HN 的理由。README 已提供准备路径，真实推理仍需要用户自行准备主模型、专家 blob 和 MTP 权重，并透明披露资产、磁盘与硬件门槛；`--demo` 只能体验界面，不能验证性能结果。

## 验证标准

- 英文 README 中不存在未翻译的中文正文，语言切换入口除外；
- 中文 README 内容完整，内部相对链接仍然有效；
- 两版 README 的数字、命令、环境变量和文件路径一致；
- GitHub 仓库链接、演示链接、许可证与贡献文档链接有效；
- HN 标题简洁，不把 32 GB 测试机误导成 8 GB 设备；
- 首评事实提纲列出硬件、结果、限制和期望讨论的问题，但不形成可直接发布的评论；
- 不在 HN 标题或评论中请求 upvote、comment 或 GitHub Star，不把 GitHub Star 与 HN 投票混淆；
- 若作者选择发布首评，必须由作者本人从零撰写，不使用生成或 AI 润色文本；
- 不出现无法由 README 或基准报告支持的性能结论。

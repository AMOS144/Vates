# README 优化设计

## 背景

当前 README 已包含项目定位、演示、核心机制、安装与使用方式、性能数据和研发历程，但缺少标准开源项目常见的徽章、技术栈、FAQ、贡献指南、许可证与联系方式等模块。部分章节篇幅偏长，快速开始路径不够突出，新用户难以快速定位可直接执行的命令。

## 目标

- 只重构 `main` 分支的 `README.md`，不修改项目功能或运行方式。
- 建立清晰、统一、符合 GitHub 阅读习惯的文档层级。
- 同时满足首次使用者快速运行和开发者理解、调试、贡献代码的需求。
- 保留原 README 中可验证的技术信息、命令、性能数据和演示链接。
- 对仓库中不存在或无法确认的信息使用 `【待补充】`，不虚构功能、命令、徽章或维护政策。

## 文档结构

README 按以下顺序组织：

1. 项目标题、一句话定位与 GitHub 通用徽章
2. 项目简介与解决的问题
3. 演示
4. 功能亮点
5. 工作原理
6. 技术栈
7. 快速开始
8. 数据准备
9. 详细使用与配置
10. 项目结构
11. 性能数据与关键研发成果
12. 测试
13. FAQ
14. 开发与贡献指南
15. License
16. 作者、联系方式与仓库地址

## 内容取舍

### 保留

- 80B MoE 约 8 GB 运行内存、13–15 tok/s、KV 缓存压缩等原有数据。
- Qwen3-Next-80B-A3B、MLX、MTP、流式专家池等项目核心定位。
- 已存在且可复制执行的安装、编译、数据准备、启动和测试命令。
- 演示封面与 Release 视频链接。
- 主要命令行参数、生产环境变量及其含义。
- 关键正确性机制和经过验证的优化结果。

### 精简

- 将“研发历程与关键成果”压缩为便于扫描的结果摘要。
- 删除重复解释、过长背景和不影响使用的过程性叙述。
- 将安装与首次启动整理为连续的快速开始流程。

### 补全

- 使用仓库真实地址生成 Stars、Forks、Issues、Last Commit、Python 与 Apple Silicon 徽章。
- 根据 `pyproject.toml` 整理技术栈及最低版本。
- 从现有安装和使用说明中整理 FAQ。
- 增加通用但不虚构具体制度的 Issue、PR 与本地验证流程。
- 仓库没有许可证文件，因此 License 明确标记为 `【待补充】`，不展示虚假的许可证徽章。
- 作者使用仓库所属账号 `AMOS144`；未提供的邮箱或其他联系方式标记为 `【待补充】`。

## 排版规范

- 使用标准 Markdown 标题、列表、表格、代码块和 GitHub 提示块。
- 代码块统一标注语言，Shell 命令使用 `bash`。
- 代码注释全部使用中文。
- 首次出现的中英文术语保持统一，后续不随意更换名称。
- 避免连续的大段文字，每段只表达一个主题。
- 仅对关键结论使用粗体，避免过度强调。

## 验证方式

- 检查 README 中所有相对路径是否指向仓库内现有位置。
- 检查安装、启动、数据准备和测试命令是否与原文及 `pyproject.toml` 一致。
- 检查 GitHub 徽章链接是否指向 `AMOS144/Vates`。
- 搜索是否存在误写的功能、部署方式、许可证或联系方式。
- 查看最终 Git 差异，确保功能代码和工作树中的未完成改动均未被修改。

## 不在范围内

- 不修改源码、配置、依赖或命令行行为。
- 不引入新的 CI、发布流程或部署方式。
- 不从其他工作树合并 DeepSeek-V4-Flash 的未完成内容。
- 不创建许可证、贡献规范或行为准则文件。
